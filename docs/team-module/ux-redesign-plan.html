Collage AI · Team Learning

UX Redesign Plan

One spine — the activity. Everything else is a stage or a cut.
Draft for review Pilot: Sept 2026 (AP 50-style team-based learning) From a 6-lens UX audit + 3 redesign proposals
01

The problem

Team-based learning is one clean loop: upload a brief → students write an immutable individual prep → prep gates the team stage → the team produces a final → faculty approve & release AI-suggested grades → students see grades. The trouble is that the navigation describes a different, imaginary product.

The three-tab spine is a dead tab (Library = permanent “coming soon”), a decoy tab (Create is a lesson-builder in an app with no builder), and a junk drawer (Team secretly owns activities, roster, analytics, OCR review and grading).

Nothing tells faculty what to do next — the lifecycle badges are decorative, grading is orphaned unrouted code, prep review is buried three levels deep, and every activity opens the same hard-coded demo team. That is the “reactive patchwork” feeling. The fix isn’t more polish; it’s a new spine.

02

The one idea

Make the activity the spine. “Team”, “grading”, and “OCR review” aren’t places — they’re stages of an activity. So the workspace becomes a status-driven stepper — and it all lives inside one renamed tab. The nav itself stays a light touch (your call): keep three tabs, rename two to what they actually do.

04

Faculty journey — one stepper inside an activity

Driven off the status the data already carries. Each stage exposes exactly one navy next-step action. The stepper is always-visible and freely navigable — guidance, never a hard gate.

Stage 1
Set up
Upload the brief; pick final mode (team vs individual grade); set deadline & points. Confirm the class teams apply.
Open prep for students →
Stage 2
Prep
Per-student done / late / missing roster, with inline transcription review + zoomable scans on the row. The prep gate lives here.
Start team stage →
Stage 3
Team stage
Opens on all N teams (prep %, discussion, submission). Drill into one team’s resources, discussion & AI report.
Close & grade →
Stage 4
Grade
The AI-suggested rubric beside its evidence, editable — per team or per student. Wires up the orphaned grading code.
Approve & release →
05

Student journey — a 4-step stepper

Always visible (“Step 2 of 4”). Cards route to the real current stage; the three-hop final maze collapses to one screen.

Step 1
Prep
Answer the questions — this is your immutable original. Handwriting? Transcription review opens inline, no route jump. “Your photo is locked forever; fix misread symbols so your team can read it.”
Step 2
Team
Unlocks after you submit prep (a plain, tappable inline row — not a dead tooltip). See teammates’ originals and discuss.
Step 3
Final
One screen, not three: shared draft + inline “confirm participation” + a single Submit. (Or the individual final.)
Step 4
Grade
Hidden until a submission exists. On release: rubric score + feedback shown beside the graded answer, with a link back to the preserved original.
06

Design principles

  1. The activity is the product. Prep, teams, review, grades all live inside one activity as status-driven stages. The top nav is deliberately thin so the journey lives where the work is.
  2. Status drives the screen. The lifecycle the data already carries becomes an active stepper with exactly one recommended next-step per stage — orientation, never a hard gate. Every reached stage stays freely navigable for messy real-classroom cases.
  3. One primary action per screen. Exactly one navy button, for that screen’s main verb; everything else is ghost. If a screen has no single obvious action, it shouldn’t exist in the pilot.
  4. One home per object, shallow. An activity, a team, a response, a grade each live in exactly one place; nothing important is more than two clicks deep.
  5. One learnable pattern. The row title opens a list item; tabs navigate, chips/segmented filter; one neutral empty-state (amber only for real problems); one name per feature (“Prep responses”; the subset is “Needs review”).
  6. Cut over add; defer, don’t delete. This is a pilot. Decoys, duplicates, and fakes get removed now — and framed to stakeholders as deferred, so nobody thinks a shipped capability vanished.
  7. Only two rules are sacred. The student’s original prep is locked and preserved forever, and prep gates the team stage. Everything else in the lifecycle is advisory.
07

Highest-leverage changes

1 · Give grading a home — wire the orphaned code in as the Grade stage.
BeforeThe approve/release pipeline is unreachable dead code; the only grade surface is a read-only table hidden in Analytics.
AfterGrade is stage 4: AI-suggested rubric beside its evidence, editable, “Approve & release.” The terminal step finally exists.
2 · Move OCR / prep review out of Analytics and into the Prep stage.
BeforeTeam → Analytics → a stat tile → “Student responses.” Three levels deep, detached from the activity and its gate.
AfterA per-student prep roster on the activity, inline transcription review on each row, gate stated in place.
3 · Make one activity span all its teams.
BeforeEvery activity opens the same hard-coded single team; no way to run/monitor the class.
AfterTeam stage opens on all N teams with a switcher; click one to drill in.
4 · Simplify team formation (a section inside Activities) — lead with the roster + one “Form teams” action.
BeforeFour to five stacked controls (target size, mode toggle, scope dropdown…) before a single team is visible.
AfterTeams show immediately; one “Form teams” auto-distributes the roster (Random / Balanced); everything else in a slim toolbar.
5 · Enforce interaction consistency across every screen.
BeforeA flat field of equal-weight buttons, four “open a list item” patterns, five “pick one of N” idioms, three names for transcription.
AfterOne navy primary per screen; row title opens; tabs navigate / chips filter; one empty-state; one name.

Cut list — for the pilot

Deferred, not deleted. Removing these is most of the fix.

×
The dead create-cards — Lesson / Assessment / Flashcards / Worksheets that all route to “coming soon.” Course Designer (was Create) stays, but its cards should point at real destinations or be hidden until real.
×
The flat Activities / Teams / Analytics sub-tab row — inside the renamed Activities tab, reorganize around the activity spine instead of a flat sub-tab strip.
×
The vanity Analytics dashboard — 4 stat cards + a bar chart. Defer it; its one live number becomes an attention count on the Activities list; a light reflection view can live on an activity’s Released stage.
×
Per-activity teams — the same/per-activity toggle + “Teams for” scope dropdown (built earlier today). One stable set of class teams.
×
“Target team size” as a header slot — inert; fold into the Form-teams flow.
×
Student audio “Record discussion” — faked (fabricated duration, no playback, saves to a tab that doesn’t exist). Cut, including the copy.
×
The Faculty ⇄ Student view toggle — it silently swaps the IA. The real student app is the source of truth.
×
The Source / Resources / Discussion / Progress tab set — brief → Set-up content, resources/discussion → team-stage drill-down, AI progress → evidence in Grade.
×
Auto-magic team identity — round-robin auto-roles, auto-naming, and “let them self-assign” copy that does nothing. Defer to simple inline touch-ups.
09

Build order

  1. Rebuild the activity workspace core: multi-team + status-driven, with the stepper.
  2. Wire Grading in as the Grade stage (suggest → edit → approve & release).
  3. Move OCR / prep review into the Prep stage.
  4. Only then collapse the top nav to Activities · Students and remove the cut items.
Why this order: the new spine promises stages that don’t exist yet. Build the core first — otherwise we ship a prettier patchwork with the same dead center.
